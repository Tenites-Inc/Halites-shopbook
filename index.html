Payment rails

The ways to pay that are switched on for shops in this pilot. Adding one is configuration, not a rebuild.

How a payment is routed

  • The customer picks the wallet they use; ShopBook sends the request to that rail.
  • Money goes straight into the shop’s own account on that rail. Halites never holds it.
  • A sale completes only when that rail confirms it. A screenshot or SMS never counts.
  • If a rail goes quiet, the sale waits as unknown, so no one pays twice.

Adding a new rail

  • Halites builds the adapter and tests it in the rail’s sandbox.
  • Security and reconciliation checks pass on test payments.
  • One ops person asks to switch it on; a second approves.
  • It shows in every pilot shop’s wallet picker straight away.
